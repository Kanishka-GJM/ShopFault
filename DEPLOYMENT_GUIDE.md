# ShopFault Store — Deployment & Operations Guide
## CSI Inter-College Debugging Championship

This guide explains how to deploy and operate the **ShopFault Store** website for concurrent access by **45 competing teams (180 participants)** during a 40-minute debugging sprint.

---

## 1. Concurrency & Isolation Architecture

- **Zero-Cost Local Architecture:** The entire website runs as a client-rendered React single-page application (SPA).
- **Session Isolation:** All cart operations, order history, coupon states, and bug report submissions are isolated in each client browser's `localStorage` and `sessionStorage`.
- **Zero Cross-Contamination:** An action performed by Team 1 (e.g. adding items to cart, completing orders, or applying coupons) will **never** alter or interfere with Team 2's session.
- **Concurrent Scaling:** Because all logic runs in the browser, a single local server or free cloud CDN can easily serve thousands of concurrent requests with negligible CPU usage.

---

## 2. Option A: Local Area Network Deployment (Recommended for On-Campus Events)

This method requires **no internet connection**, costs $0, and ensures zero latency across campus Wi-Fi or college lab networks.

### Steps:
1. Ensure Node.js (v18+) is installed on the host computer.
2. Open terminal in the project directory:
   ```bash
   cd "shopfault"
   npm install
   npm run dev -- --host 0.0.0.0 --port 5173
   ```
3. Locate the host computer's Local IP address:
   - **Windows:** Run `ipconfig` (Look for IPv4 Address, e.g. `10.94.148.120` or `192.168.1.50`).
   - **Linux/Mac:** Run `ifconfig` or `ip a`.
4. Share the URL with participants:
   ```
   http://<HOST_IP>:5173/
   Example: http://10.94.148.120:5173/
   ```
5. All 45 teams on the same local Wi-Fi / LAN can access the site simultaneously.

---

## 3. Option B: Free Cloud Hosting (Vercel / Netlify / Render)

If participants are joining remotely or from different networks, deploy to a free global CDN.

### Vercel Deployment (Fastest):
1. Install Vercel CLI (optional) or push code to GitHub:
   ```bash
   npm run build
   npx vercel deploy --prod
   ```
2. Or connect your repository directly at [vercel.com](https://vercel.com):
   - **Build Command:** `npm run build`
   - **Output Directory:** `dist`
3. Vercel provides an instant HTTPS URL (e.g. `https://shopfault-store.vercel.app`).

### Netlify Deployment:
1. Run `npm run build`.
2. Drag and drop the generated `dist/` folder into [app.netlify.com/drop](https://app.netlify.com/drop).
3. The site goes live immediately with a stable URL.

## 4. Keeping Organizer Materials Strictly Private

To preserve competition integrity:
1. **Answer Key Separation:**
   - Do **NOT** publish `ORGANIZER_ANSWER_KEY.md` or `BUG_VERIFICATION_CHECKLIST.md` to a public repository or shared team drive.
   - These documents should remain exclusively on the organizer machines or private flash drives.
2. **Built-in Organizer Portal Protection:**
   - The built-in Organizer Portal within the web app requires a confidential PIN:
     - **Default Organizer PIN:** `shopfault-admin-76` or `organizer2026`
   - Participants cannot open the answer key or checklist without this passcode.
3. **No Hints in Source Comments:**
   - The production bundle generated by `npm run build` minifies all JavaScript and strips developer comments.

---

## 5. Participant Submission Workflow

During the 40-minute sprint:
1. Participants discover anomalies on the website.
2. They click the **Bug Submission Portal** button in the navigation bar.
3. They fill in:
   - Team Name / Team ID
   - Affected Page / Module
   - Suspected Bug Title
   - Numbered Steps to Reproduce
   - Expected Behaviour vs Actual Behaviour
   - Estimated Difficulty
4. Upon submission, reports are stored with a unique ID and timestamp.
5. At the end of the sprint, teams click **Export Reports (JSON)** and upload their file to the event submission drive or Google Form.
